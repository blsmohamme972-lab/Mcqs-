You are authoring a **content package**, not changing the Kafu platform.

## Inputs you must receive

1. One or more Kafu MCQ text exports with:
   - `export_type: "kafu_mcq_text_export"`
   - `schema_version: 1`
2. A selection request:
   - exact QIDs, or
   - an exact count.
3. Duration:
   - one integer duration for the batch, or
   - explicit per-QID overrides.

Do not invent missing QIDs, fetch unrequested chapters, or convert the export by hand.

## Real export fields

Use:
- QID: `questions[i].id`
- Book: `questions[i].book_id`
- Version: `questions[i].version`
- Chapter: `questions[i].chapter_id`
- Content: `stem`, `lead_in`, `type`, `options`, `answer`, `explanation`, image references.
- Integrity rows: join `export_metadata.question_integrity[*].qid === questions[i].id`.

The tooling verifies:
- `publisher_fingerprint`
- `content_hash`
- `SHA-256`
- `kafu-question-canonical-json-v1`.

Never hand-type replacement hashes.

## Scope compatibility

Some older chapter exports were incorrectly labelled `scope.type: "book"` because the UI passed `chapterId` while the exporter read `chapter_id`.

The adapter therefore trusts the actual supplied question records plus matching chapter metadata, not the bad label. Example: 209-question book metadata with exactly Q000007341–Q000007370 supplied and a matching 30-question Upper Limb chapter becomes a **30-record chapter selection with a warning**. Never claim the other 179 records were supplied.

Partition metadata is interpreted per part. A part's `question_count` is not the aggregate exported count.

## Correct answers

Correct-answer text is generated by tooling from the **original options array**, before any Kafu screen shuffling:
- SBA / EMQ: A → option index 0, B → 1, etc.
- Multi: every encoded answer letter is resolved.
- MTF: every statement is paired with its T/F value.
- Unsupported/ambiguous encoding is blocked, never coerced.

Do not rewrite, medically correct, soften, or replace the source answer.

## Selection

For exact QIDs, every requested QID must be present and valid. Never silently substitute a blocked item.

For count-only requests, default is deterministic: **first N eligible supplied records in source order**.

Only choose by "visual usefulness" when the owner explicitly asks you to do so. In that case, record the chosen IDs before authoring and pass those exact QIDs to the scaffold command.

Duration bounds are 2000–30000 ms inclusive. Missing duration is an error unless the owner explicitly approved a default. The end panel remains readable after the timeline stops and does not count toward `duration_ms`.

If a question references a figure essential to the concept, inspect the actual approved source image bytes first. If they are unavailable, mark the item blocked. Never guess image content.

## Authoring commands

Scaffold:

```bash
python tools/motioncards.py scaffold exported.json \
  --out work/my-batch \
  --package-id MY-BATCH \
  --revision 1 \
  --qids Q000000001 Q000000009 \
  --duration-ms 8000
```

Per-QID duration:

```bash
python tools/motioncards.py scaffold exported.json \
  --out work/my-batch \
  --package-id MY-BATCH \
  --revision 1 \
  --qids Q000000001 Q000000009 \
  --duration Q000000001=6000 \
  --duration Q000000009=10000
```

Count-only:

```bash
python tools/motioncards.py scaffold exported.json \
  --out work/my-batch \
  --package-id MY-BATCH \
  --revision 1 \
  --count 20 \
  --duration-ms 10000
```

Preview:

```bash
python tools/motioncards.py preview --workspace work/my-batch --port 8767
```

The preview command serves a **trusted loopback host player** with the real MessageChannel/timeline contract, host-owned controls, and the source-derived final panel. Open the host page listed by the preview index; do not treat a raw child `.html` entry as a functioning preview. Loopback HTTP is permitted only in this explicit preview mode. Production entries remain HTTPS-host restricted.

Voice-over (required: every new card ships with voice; see `voiceover/README.md`, the Golden 8 Rules):

**Ask the owner first which voice engine to use** (one question per batch, before any voice is made): **Kokoro** (free, offline, the default) or **ElevenLabs** (paid API, needs `ELEVENLABS_API_KEY`). If they want to hear both, run `voiceover.py sample` and send them the two 7-second clips. Never pick for them: `make` refuses to run without `--engine`.

```bash
voiceover/bootstrap.sh                                                        # once per machine
~/.venvs/kafu-voice/bin/python voiceover/voiceover.py sample                  # optional: 7 s test clip per engine -> work/voice-sample/
~/.venvs/kafu-voice/bin/python voiceover/voiceover.py make --engine <kokoro|elevenlabs> --workspace work/my-batch
```

`make` reads each card's numbered captions aloud, fits every line inside its animation beat, and checks pronunciation and sync by listening back. Shorten the lines it lists, then run it again until it says DONE. Keep captions short and speakable (about 6 / 5 / 6 words on an 8 s card) so no edits are needed.

Package (refuses a card without voice; `--no-voice` exists only for re-packaging old silent cards):

```bash
python tools/motioncards.py package exported.json \
  --workspace work/my-batch \
  --out dist/MCARDS_MY-BATCH_r1.zip
python tools/motioncards.py validate dist/MCARDS_MY-BATCH_r1.zip
```

## Scene contract

Edit only `work/<batch>/scenes/Q#########.scene.json`.

**Author new cards with schema v2: read `AUTHORING_V2.md` (compact reference) and the `examples/v2-*.scene.json` gold examples.** **Build anatomy on the bundled art library (`python tools/motioncards.py library`, then `import-svg lib:<name>`) and shade anything you draw with the style kit (`style-kit`); do not hand-draw organs.** **Take outside art only from the approved sources table in `AUTHORING_V2.md` (in its order), with the credit form given there.** Best sources, in order: Servier SVGs on [bioicons.com](https://bioicons.com/) (organs, food, weather, animals, objects), then Servier SMART at [smart.servier.com](https://smart.servier.com/) (people, patients, lifestyle; cut drawings out of its `.pptx` sets with `tools/motioncards_smart.py`). The full list is "Where to find art" in `AUTHORING_V2.md`. **Animate with the tested recipes (`motioncards.py recipes`, table in `AUTHORING_V2.md`) before writing custom animation code.** **If you made a reusable drawing or animation the library lacks, propose it ("Improving the library" in `AUTHORING_V2.md`); only clear improvements pass the automatic gate.** For professional or precise cards use v2 *free mode*: plain SVG plus a JavaScript `render(t, api)` with full DOM access inside the sandbox. v2 adds:
- easing;
- separate visibility (`show`) and motion (`keys`);
- enter/exit presets;
- scaling and rotation around each shape's own centre;
- path morphing and drawn-on lines;
- motion along paths, particles, spotlight and camera;
- text wrapping and labels;
- gradients, shadows and embedded raster illustrations.

Required in every scene:
- `schema_version` (`2` for new cards; `1` is the legacy engine and stays supported byte-for-byte)
- exact `qid`
- exact `duration_ms`
- one short `takeaway`
- `layers`

The authoritative host timeline drives every frame. Do not use CSS animations or independent timers. Free-mode code runs inside the sandboxed, network-less iframe. Timers are inert, `Math.random` is seeded, and `render` must be a pure function of `t` (the `render` command verifies this).

Legacy v1 scenes use `start_ms`, `end_ms`, `from`, `to` with the primitives `label rect circle arrow path highlight focus` (see `TOOLKIT.md`).

## Educational rules

Teach only the key relationship needed to understand the source-correct statement.

Prefer movement, direction, emphasis and spatial relationships to prose.

Use short labels and essential numbers. Avoid paragraphs, decorative loops, unrelated anatomy and distractor discussions unless the answer meaning depends on order/comparison.

Default silent.

At completion, Kafu's trusted host displays:
- **Takeaway** — from your validated scene source.
- **Correct answer** — generated by the packager from the original source answer.

Do not put an invented answer into the scene.

## Timeline and player

The scene is compiled into one self-contained HTML entry. It must not load network resources.

The Kafu host owns Play/Pause/Restart/Seek and the monotonic clock. The iframe only renders the timestamp it receives.

Required protocol version: 1.

Messages are channel/QID bound. The child accepts a MessageChannel only from the configured Kafu host origin and parent window.

The compiled scene runs in a restricted iframe with `sandbox="allow-scripts"`. Do not require same-origin, forms, popups, downloads, Telegram SDK, cookies, IndexedDB or application state.

## ZIP contract

Filename:

`MCARDS_<PACKAGE-ID>_r<N>.zip`

Optional multipart intake may use:

`MCARDS_<PACKAGE-ID>_r<N>_partXofY.zip`

The root manifest is always:

`motioncards-manifest.json`

It includes:
- package type / schema
- package identity and revision
- runtime and protocol versions
- source provenance
- selected QIDs
- per-animation source identity and full content hash
- requested duration
- compiled entry path and SHA-256
- editable scene path and SHA-256
- selected original source record path and SHA-256
- source-derived final answer metadata.

The package may contain only approved MotionCards paths. It must not contain workflows, server handlers, service workers, `_worker.js`, `_headers`, `_redirects`, executable files or package-manager files.

Do not include unrelated source questions.

The current incoming ceiling is **19 * 1024 * 1024 bytes = 19,922,944 bytes**. The validator also enforces entry count, expanded bytes and compression-ratio limits.

## Validation before delivery

Run:

```bash
python tools/motioncards.py lint --workspace work/my-batch
python tools/motioncards.py render --workspace work/my-batch --out work/my-batch/render
python -m unittest tools.tests.test_motioncards_authoring -v
python tools/motioncards.py validate dist/MCARDS_MY-BATCH_r1.zip
```

`lint` fails on any invalid scene with the exact field path and prints layout warnings. `render` (requires `pip install playwright` and a Chromium) writes PNG frames plus one `<QID>_sheet.png` contact sheet per card at phone and tablet framing. It fails if the card reports a render error or if seeking backwards does not reproduce the same frame. Look at the sheet and fix what looks wrong before packaging.

Then visually inspect each authored animation at:
- start
- at least one intermediate timestamp
- completion
- narrow phone framing
- tablet framing
- reduced motion.

A schema PASS is not a medical-quality review.

The validator also rebuilds deterministic compiled entries from the validated scene source and pinned runtime, then compares the exact bytes. Do not edit compiled HTML or replace it with a blank/custom file and update the checksum. Publish-ready scenes reject unfinished `EDIT:` takeaways and non-boolean replacement intent.

## Replacing an existing published card

Content authors still create an ordinary narrowly scoped MotionCards ZIP. Do **not** manually edit state or hashes and do not rebuild unrelated cards.

If the selected QID already has an active MotionCard:
1. Keep the requested replacement QID(s) only.
2. Set `replace: true` as a genuine JSON boolean in the validated scene source.
3. Package and validate normally.
4. Upload the ZIP to the existing owner bot.
5. The platform validates the candidate and shows the owner the exact cards that would be replaced.
6. Publication waits for the owner's explicit expiring confirmation. A stale `replace:true` flag alone is never authorization.

Removing/restoring published cards is an owner platform-management action via `/motioncards QID`, not a content-authoring task.
